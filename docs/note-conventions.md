# Blog 笔记规范

本规范用于统一 Blog 中新增笔记的目录、文件名、标题、时间和版本。目标是让人和 Agent 都能快速找到、追加和汇总笔记。

## 1. 基本原则

1. 文件名用于稳定链接和检索，统一使用小写英文、数字和短横线（kebab-case）。
2. 页面标题面向读者，正文名称可以使用中文，但标题中的日期仍必须使用数字格式。
3. 文件名和文章标题中的日期统一使用 `YYYY-MM-DD`；季度使用 `YYYY QN`。日期中禁止出现“年、月、日”，也不要使用 `20260823` 这种无分隔格式。
4. 新笔记默认使用创建当天的日期；只有需要保留多个历史版本时才增加版本号。
5. 已发布文章原则上不改文件路径，避免旧链接失效；规范主要约束新文件。

## 2. 通用文件命名

```text
<领域>-<类型>-<周期或日期>[-<主题>][-v版本].md
```

字段说明：

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| 领域 | 笔记所属领域 | `invest`、`thinking`、`tech` |
| 类型 | 笔记用途 | `checklist`、`case`、`record`、`summary` |
| 周期或日期 | 季度、年份或具体日期 | `2026-q3`、`2026`、`2026-08-23` |
| 主题 | 公司或具体主题，可省略 | `beyond-meat`、`intel` |
| 版本 | 同一周期内的正式修订版本 | `v1`、`v2` |

示例：

```text
投资-检查清单-2026-08-23.md
投资-检查清单-2026-v1.md
投资-案例复盘-2026-08-23-beyond-meat.md
投资-记录-2026-08-23.md
学习-价值投资-2026-08-23.md
日志-2026-08-23.md
```

不要使用以下形式（特别是文件名或标题中带“年、月、日”的日期）：

```text
投资-检查清单-2026年8月23日.md
invest_checklist_final_final.md
新建文档1.md
```

## 3. 目录规则

所有分类文章统一按 **`content/post/<分类>/<年份>/<具体文件名>.md`** 存放，不额外嵌套多余的子目录：

```text
content/post/<分类>/<年份>/<具体文件名>.md
```

示例：

```text
content/post/invest/2026/投资-不为清单-2026-10-24.md
content/post/invest/2026/投资-检查清单-2026-08-23.md
content/post/thinking/2026/2026-0103.md
```

## 4. 标题与封面图规则

### 4.1 标题规则

标题统一采用 **`<主题或系列名称>｜<YYYY-MM-DD>`** 格式（前面是名称，后面用全角竖线 `｜` 连接日期）。标题不添加难以理解的内部缩写。日期规则与文件名相同：具体日期使用 `YYYY-MM-DD`，年份使用 `YYYY`，不出现“年、月、日”。推荐格式：

```text
我的投资不为清单（Stop Doing List）｜2026-10-24
我的投资检查清单之一：Beyond Meat｜2026-08-23
我的投资检查清单之二：万科｜2026-08-28
投资记录：李录哥大分享与冯仑对谈有感｜2026-10-24
```

禁止使用：

```text
投资记录｜2026年8月23日
2026年投资总结
```

普通笔记不添加版本号，直接持续修改并更新 `lastmod`。只有确实需要同时保留多个历史版本时，文件名才增加 `v1`、`v2`，标题对应显示“第1版”“第2版”。

### 4.2 封面图（Cover Image）生成与使用规则

1. **比例与构图**：统一使用 **`2.5:1`** 横幅比例（如 `1376 × 550`）。由于首页列表卡片会做垂直居中裁切（`object-fit: cover`），核心主体与文字必须放在画面垂直居中安全区内。
2. **视觉风格（固定两类简洁风格）**：
   - **风格一（清单/原则/方法论类）**：温暖纪实桌面摄影风——木质书桌、摊开的米白色笔记本上用钢笔手写核心英文标题（如 `Stop Doing List`），搭配钢笔与咖啡杯，自然光影。
   - **风格二（人物访谈/演讲/特定公司类）**：高清纪实人物或真实场景图，构图简洁留白，可在留白处辅以克制的文字标题。
   - **禁忌**：不使用花哨的渐变色块、廉价的扁平矢量图标拼贴。
3. **路径**：投资类图片统一放在 `static/invest/`，Front Matter 中写 `image: /invest/xxx.jpg`。

## 5. Front Matter 规则

每篇新笔记至少包含：

```yaml
---
title: "我的投资不为清单（Stop Doing List）｜2026-10-24"
date: 2026-10-24
lastmod: 2026-10-24
draft: true
image: /invest/stop-doing-list-cover.jpg
description: ""
tags: [股票, 投资复盘, 检查清单]
categories: [投资]
---
```

- `date`：首次创建日期，后续不修改。
- `lastmod`：每次有实质内容修改时更新。
- 新笔记默认 `draft: true`，完成校对后再发布。
- `description` 默认留空（`""`），保持卡片和页面顶部干净整洁；仅在用户明确要求时填写简短一句话说明。

## 6. 投资笔记专用规则

### 6.1 两类文档

投资复盘分为两层：

1. **案例复盘**：保存某家公司当时的判断、证据、结果和错误。
2. **检查清单**：只收录能够在下一次买入前执行的问题。

不能只因为股价上涨或下跌就新增检查项。新增项必须来自可解释的判断错误，并写明“未通过时采取什么行动”。

### 6.2 判断与结果分开

每个已结束或阶段性复盘的案例，必须归入以下一种：

| 判断 | 结果 | 分类 |
| --- | --- | --- |
| 看对 | 赚钱 | 正确且成功 |
| 看对 | 亏钱 | 正确但失败 |
| 看错 | 赚钱 | 错误但成功 |
| 看错 | 亏钱 | 错误且失败 |

尚未获得足够证据时标记为“开放中”，不得强行归类。

### 6.3 日期与版本

- 日常检查清单：`投资-检查清单-YYYY-MM-DD.md`
- 年度汇总：`投资-检查清单-YYYY-vN.md`
- 每次正式复盘可以按当天日期新建清单，不覆盖以前的清单。
- 同一天继续补充时直接更新原文件；只有需要保留修改前后的两个版本时才增加 `v1`、`v2`。
- 只修正错别字不升级版本，但需要更新 `lastmod`。

### 6.4 每个案例的必填信息

1. 行业大类、细分行业和商业模式。
2. 当时为什么买入或关注。
3. 当时依赖的核心假设。
4. 当时已有的事实与证据。
5. 可以证明判断错误的条件。
6. 后来实际发生了什么。
7. 判断质量与投资结果分别如何。
8. 能否提炼成下一次可执行的检查项。

信息缺失时应写“待核对原始记录”，不要用事后记忆冒充当时判断。

行业分类统一使用：

```text
一级行业｜二级行业｜业务标签
```

- 一级行业优先从消费、科技、金融、医药、能源、工业、房地产、材料、公用事业、通信中选择。
- 二级行业说明主要生意，例如包装食品、半导体、住宅开发。
- 业务标签进一步说明产品或模式，例如植物蛋白、芯片设计与制造。
- 分类以公司的主要收入来源和商业模式为准，而不是宣传用语或采用的技术。技术赋能的食品公司仍归消费；半导体归科技，并在二级行业注明半导体。

示例：

```text
Beyond Meat：消费｜包装食品｜植物蛋白
Intel：科技｜半导体｜芯片设计与制造
万科：房地产｜住宅开发｜住宅销售与物业服务
```

### 6.5 案例表格结构

个人投资检查清单采用一家公司一篇文章，不在单篇文章中预列尚未复盘的公司。若以后另建系列总目录，索引只保留编号、公司、行业分类、复盘状态和当前分类。

每家公司单独使用完整的四列表格：序号、复盘项目、当时情况、复盘结论。例如：

```text
## 案例001：公司名称

| 序号 | 复盘项目 | 当时情况 | 复盘结论 |
| --- | --- | --- | --- |
| 01 | 行业与商业模式 | 当时了解的情况 | 正确的行业分类和盈利方式 |
| 02 | 买入原因 | 当时的真实买入理由 | 哪些理由有效，哪些存在偏差 |
| 03 | 核心假设 | 当时相信什么 | 假设后来是否成立 |
| 04 | 遗漏问题 | 买入前没有回答什么 | 遗漏造成了什么风险 |
| 05 | 最终评价 | 判断、行动和结果 | 可以沉淀什么检查项 |
```

回答较长时，可以在纵向表格后增加独立小节展开，但表格本身必须能够呈现完整的判断链条。

### 6.6 买入前检查清单

每家公司统一从以下七个维度分析，不随案例增加或删除一级分类：

1. 行业
2. 能力圈
3. 商业模式
4. 护城河
5. 企业文化
6. 财务与估值
7. 投资策略

单个案例产生的新问题，应放入对应维度的核心问题或注意事项中。例如，消费品的复购和口味习惯归入商业模式与护城河；名人背书和个人信仰归入能力圈；估值和安全边际归入财务与估值；仓位、买卖计划、退出和证伪条件归入投资策略。

清单表格固定使用五列：

```text
序号｜检查项｜核心问题｜注意事项｜通用原则
```

- 公司的具体核心问题放入公司七项分析表，不放进通用检查清单。
- 通用问题：从具体案例中抽出以后分析任何公司都要回答的问题。
- 注意事项：记录本案例暴露的风险、偏误和证据要求。
- 通用原则：把案例教训抽象成以后分析其他公司时可以重复使用的规则。

检查项借鉴莫尼什·帕伯莱的方法生成：

1. 找一个真实失败或明显偏离预期的投资案例。
2. 解释投资为什么失败，不以股价涨跌代替原因分析。
3. 判断失败原因在买入前是否已有可见证据。
4. 找出当时没有回答的问题，归入固定七个维度。
5. 把公司专属问题抽象成可以用于其他公司的通用问题。
6. 完成公司研究后、正式买入前运行清单。
7. 关键问题答不清时停止买入，补充研究后重新运行。

清单不要求公司没有问题，而是帮助投资者看见问题，再决定风险是否可以理解和承受。
